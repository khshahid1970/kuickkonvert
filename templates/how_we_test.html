How We Test KuickKonvert’s Tools

By Shahid Iqbal · Published {{ nice_date(published) }}

Every result we quote on KuickKonvert comes from a test we ran ourselves. We make test files on a computer, convert them with the same code the live site runs, in a test copy of the site, and write down the date, the files and the numbers. For example, in September 2026 our Compress PDF code took a 3.2 MB PDF holding one photo down to 50 KB on its “Smallest file” setting.

What do we test, and how?

  1. We make the test files ourselves: Word documents, spreadsheets, slides, photos, screenshots and PDFs, made on a computer for the test. We never use visitors’ files. Uploads are deleted automatically after conversion and are never reviewed.
  2. We convert them in a test copy of the site that runs the same code and the same settings as the live tools, for example the same Ghostscript presets for Compress PDF and JPG quality 90 for the image converters. The software versions in the test copy can differ slightly from the live server’s, so where it matters a guide names the version it used (for example Ghostscript 10.02.1).
  3. We measure what changed: file size in KB, number of pages, whether the text can still be selected and searched, which photo details are kept or removed, and whether a protected PDF really needs its password.
  4. We write the result down with the month of the test and quote it on the page it belongs to.
  5. Before any change goes live, we convert sample files with every tool on the test copy and check the results, and more than 180 automatic checks run on the site’s code.

Where can I download the test files?

Two sets of test files and results are published on Zenodo, a research archive run by CERN, under the CC BY 4.0 licence, so anyone can check or repeat them:

  • 13 November 2026: five tests (PDF compression presets, DOC vs DOCX, PDF page to PNG and JPG, PNG to JPG, PowerPoint to PDF), with every test file and script. DOI 10.5281/zenodo.24199944. This was a separate run with different files from the September and October tests quoted in some guides, so its numbers differ from theirs. One example: a 9,199.2 KB PNG photo became a 1,135.0 KB JPG at quality 90, and a logo’s transparent background turned white.
  • 17 November 2026: how much bigger a file gets when it is attached to an email. The email was 36.8% bigger than the file itself, so an email limit of 25 MB leaves room for a file of only about 18 MB. DOI 10.5281/zenodo.24324333.

Suggested citations:

  • Iqbal, S. (2026). Email attachment encoding test: how much bigger a file gets when attached to an email (2026). KuickKonvert. Zenodo. https://doi.org/10.5281/zenodo.24324333

Why might your result be different?

Our numbers describe our test files, not yours. A PDF full of photos shrinks far more than a typed report, which can even come out slightly larger, so Compress PDF gives you the original back instead of a bigger file. Fonts matter too: a document in a font our server doesn’t have is set in another font and can gain a page. Scanned pages are pictures, so PDF to Word gives you pictures of the text, not editable text, because our tool doesn’t do OCR. Always open the converted file and check it before you send it.

Who runs the tests?

The tests are run and written up by Shahid Iqbal, who runs KuickKonvert. If one of your files gives a very different result from a test on this site, email {{ obfuscated_mailto('info@kuickkonvert.com') }} with the tool name and the file size, and we will look at it. The full source code of the site is public on GitHub, so the settings described here can be checked. More about the site is on our About page.
